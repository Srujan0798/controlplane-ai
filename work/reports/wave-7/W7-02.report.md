# W7-02 — Idempotency-Key support

## What was done

Honors `Idempotency-Key` on the demo and chat admission endpoints. Same key + same body → same cached response (no double-commit). Key reused with a DIFFERENT body → `409 Conflict` (no silent re-commit).

## Files changed
- `controlplane/idempotency.py` (new) — `IdempotencyCache` (in-memory, TTL via `CONTROLPLANE_IDEMPOTENCY_TTL_S` default 300s, thread-safe), `fingerprint()` canonical sha256 of decision inputs, `lookup`/`store`/`conflict`.
- `controlplane/server/app.py` — import `idempotency`; `idem_cache = idempotency.IdempotencyCache()` in `create_app`; `run_demo` now takes `request: Request`, checks header, replays/conflicts; chat-completions scenario block mirrors the same check and caches the full completion.
- `tests/test_idempotency.py` (new) — same key+body replays; different body → 409; different keys both run; chat same key replays; no-key runs normally.
- `.env.example` — added `CONTROLPLANE_IDEMPOTENCY_TTL_S=300`.

## Conflict policy
A key reused with a different body fingerprint returns `409 Conflict` (preferred over replay, so a caller learns their retry changed). Documented in report + test.
