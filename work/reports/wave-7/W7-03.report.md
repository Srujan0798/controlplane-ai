# W7-03 — Structured JSON logs

## What was done

One JSON object per line on stderr; decision lines carry gate metadata only (request_id, scenario, mode, latency_ms, actuators, would_hold, enforced). No claim text, span content, or prompt bodies on the log path (no PII sprawl).

## Files changed
- `controlplane/logging_setup.py` (new) — `JsonFormatter` (ts/level/logger/msg + optional `fields`), `configure_logging()` (idempotent, attaches JSON handler to `controlplane` logger, propagates False), `log_decision(logger, public_dict, *, scenario=None)`.
- `controlplane/server/app.py` — `access_log = logging_setup.configure_logging()` in `create_app`; `log_decision(access_log, pub, scenario=scenario)` in `run_demo` and the chat-completions scenario block.
- `tests/test_logging_setup.py` (new) — formatter emits required keys; `configure_logging` idempotent; demo + chat endpoints each emit a `decision` line with correct fields and NO pii keys.
- `.env.example` — doc note: `CONTROLPLANE_LOG_LEVEL=INFO` (optional, already supported; not added to avoid duplication).
